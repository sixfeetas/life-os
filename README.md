# Life OS

记录 · 计划 · 自省 —— 纯前端单页应用，不需要服务器。

线上地址：<https://sixfeetas.github.io/life-os/>

## 电脑和手机自动同步

1. 第一次使用时，点右上角云朵按钮，填写邮箱和密码，创建账号。
2. 如果收到确认邮件，先点邮件里的确认链接；没有收到就检查垃圾邮件。
3. 电脑登录后，手机打开同一个网址，用同一个邮箱登录即可。
4. 以后修改记录会自动上传；手机切回网页或每次打开时也会自动拉取。

同步使用 Supabase。项目第一次使用需要执行
[`supabase-setup.sql`](./supabase-setup.sql) 建表，网页里也会显示建表步骤。

## 数据是怎么保护的

- 数据同时保存在本机和 Supabase 云端，断网时仍然可以先记录。
- 每台设备都有本机恢复快照，保存后会读回校验。
- 两端修改按记录合并，不会用空数据直接覆盖有数据的设备。
- AI API Key 只留在当前浏览器，不进入云端，也不进入导出的备份。
- 云端数据受 Supabase 行级权限保护，只能用各自登录的账号读取。
- 仍建议定期点右上角下载按钮导出 JSON 备份。

## 打开和安装

直接打开线上地址即可。手机浏览器里选择“添加到主屏幕”，之后就能像 App 一样打开。

不要双击 `index.html` 使用。本机文件地址通常会被浏览器禁用持久存储，数据可能关掉页面后就消失。

## 三个 tab

- **记录**：计时、情绪、补记、时间轴
- **计划**：任务卡（预估 vs 实际）、超时追问、顺延提醒
- **自省**：观点卡（3 次证据才内化）、落地率、结果锚点、AI 分析对话

## GitHub Pages

第一次发布时，打开仓库的 **Settings → Pages**，Source 选择
**Deploy from a branch**，Branch 选择 **main / (root)**，点 **Save**。
之后推送到 `main` 会自动发布，不需要再改 Pages 设置。

发布新版时，双击 `推送.cmd`。脚本会先打开 GitHub 登录页；登录完成后，
它会自动提交和上传。第一次发布后等 2-3 分钟，再打开线上地址。

## 找不到旧记录时

1. 先确认打开的是线上网址，而不是本地 `index.html`。
2. 确认使用同一个浏览器、同一个浏览器用户配置。
3. 不要先清理浏览器站点数据。
4. 如果有 JSON 备份，点右上角“从备份恢复”导入。

仓库里只有 Supabase 的公开 `anon` key，可以安全放在网页中。不要把自己的
`service_role` key 放进项目。AI API Key 只保存在当前浏览器。
